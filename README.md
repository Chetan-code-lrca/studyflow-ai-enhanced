# StudyFlow AI

A small React + TypeScript study tracker for keeping subjects, study time, assignments, and basic progress in one place.

This is a client-side app. There is no backend in the current codebase, and your data is stored in the browser's `localStorage`.

## What it actually does

The app has four sections:

- **Subjects** — add subjects, see progress against a 40-hour target, and record `+30 min`, `+1 hr`, or `+2 hr` study sessions.
- **Schedule** — see subject progress and the most recent study sessions.
- **Assignments** — add assignments with a subject, deadline, and priority; mark them complete or remove them.
- **Analytics** — total study time, study time from the last seven days, assignment completion rate, upcoming deadlines, and recommendations based on your current data.

The recommendations are generated by rules in `src/App.tsx`. They are not calls to an external AI service in this version. For example, the code checks overdue assignments, deadlines within three days, low subject progress, and subject names such as DSA, DBMS, and OS.

## Stack

- React 18
- TypeScript
- Vite 5
- Browser `localStorage`
- TypeScript compiler for the production build

The versions above come from the checked-in `package.json`, `tsconfig.json`, and Vite configuration.

## Run it locally

You only need Node.js and npm.

### 1. Clone

```bash
git clone https://github.com/Chetan-code-lrca/studyflow-ai-enhanced.git
cd studyflow-ai-enhanced
```

### 2. Install dependencies

```bash
npm install
```

### 3. Start the development server

```bash
npm run dev
```

Vite will print the local URL. The usual development address is:

```text
http://localhost:5173
```

### 4. Build a production version

```bash
npm run build
```

The build runs TypeScript checking first and then creates the production bundle in `dist/`.

To preview that bundle locally:

```bash
npm run preview
```

## GitHub Pages

This repository already contains a GitHub Actions workflow that builds the project on pushes to `main` and deploys `dist/` to GitHub Pages.

There is also a manual npm script:

```bash
npm run deploy
```

That script uses `gh-pages -d dist`.

The Vite config sets the base path to:

```text
/studyflow-ai-enhanced/
```

so the application is configured for the repository's GitHub Pages path rather than the domain root.

The workflow uses Node.js 20 in CI.

## Where the data goes

StudyFlow does not send your subjects, assignments, or study sessions to a server.

`src/App.tsx` stores these three values in browser storage:

```text
studyflow_subjects
studyflow_assignments
studyflow_sessions
```

That means:

- refreshing the page keeps your data;
- opening the app in a different browser does not share the same data;
- clearing browser storage removes the saved data;
- there is no account or cloud-sync feature in the current version.

Assignments and study-session dates are converted back to JavaScript `Date` objects when the app loads them.

## Using the app

### Add a subject

Go to **Subjects**, enter something such as `DSA`, `DBMS`, or `Operating Systems`, and click **Add Subject**.

New subjects start with a target of **40 hours**.

### Record study time

Use one of the quick buttons on a subject card:

```text
+30min
+1hr
+2hr
```

Each entry updates the subject's total and creates a study-session record.

### Add an assignment

Open **Assignments** and enter:

- title
- subject
- deadline
- priority (`High`, `Medium`, or `Low`)

The app marks assignments as overdue or urgent based on the current date. Assignments due within three days are treated as urgent.

### Check analytics

The **Analytics** tab calculates:

- total study hours across subjects;
- study hours from the last seven days;
- assignment completion percentage;
- the next five incomplete deadlines;
- subject-level progress;
- rule-based study recommendations.

## A note about "AI"

The repository name includes `AI`, but the current implementation does not use an LLM, API key, model, or hosted AI service.

The recommendation function is ordinary application logic. That is worth knowing before presenting or extending the project: adding a real AI layer would be a separate feature rather than something that is already wired into this codebase.

## Limitations in the current version

A few things are intentionally simple:

- subject targets are fixed at 40 hours when a subject is created;
- there is no way in the current UI to edit a subject's target after creation;
- there is no user account or database;
- there are no push notifications;
- there are no charts beyond the progress/summary views already rendered in the app;
- there are no automated tests checked into the repository;
- the GitHub Pages deployment is configured, but the repository does not include a separate backend or cloud data layer.
